# 대화 맥락 유지 평가 — 2026-09-28

현재 판정: **대화 연결 보강 필요, 범용 GO 보류**. 대화 내용의 저장·재개가 가능하더라도, 사용자가 유지/변경/해제한 조건과 현재 데이터 참조를 정확하게 갱신하는 것은 별도 문제다.

## 최종 집계

8종류×2회, **16여정 중9통과·7실패**, **62턴 중51통과·11실패**다. 잘못된 완료6건, 원본 digest는 실행한62턴 모두 유지됐다. 미실행 턴은0개다. 일부러 맥락 전환을 포함한 고정 묶음이므로 전체 사용자 대화의 정확도/신뢰구간으로 일반화하지 않는다.

| 여정 | 1회 | 2회 |
|---|---|---|
| 생략 참조·연산 변경·원본 복귀 | PASS | PASS |
| 조건 일부만 해제 | FAIL | FAIL |
| 설명 질문 후 분석 복귀 | FAIL | FAIL |
| 데이터 전환과 그 데이터 참조 | FAIL | FAIL |
| 재시작 후 이어가기 | PASS | PASS |
| 차트 설정만 수정 | PASS | PASS |
| 별도 세션 분리·복귀 | PASS | PASS |
| 요약 이후 8턴 분석 | FAIL | PASS |

요약 stress는 실제 요약이 두 실행에서 각각14회·13회 발생했다. 첫 실행의7번째 턴은미완료, 두번째실행은8턴전부통과로 변동성이 있었다. 최초 실패를 성공으로 대체하지 않았다.

## 평가 방식

실제 production graph와 Databricks 모델을 사용한다. 8종류 여정을 각각 새 대화에서 2회 실행하며, 한 여정 안에서는 사용자 메시지를 순서대로 제출한다. 실패한 턴 뒤 수동으로 상태를 고치거나 재개하지 않는다. 재시작·새 세션 진입은 사전에 정의한 시험 동작이다. 두 데이터셋은 같은 컬럼 이름을 가지지만 값이 달라서 다른 출처의 계산을 정답으로 오인하기 어렵게 구성했다.

턴마다 외부 fixture에 기대 출처·계산 컬럼·연산·독립 수치 또는 차트 설정/입력값을 고정했다. 정답은 모델에 제공하지 않는다. scalar는 실제 결과 dataset의 값·SQL 집계 컬럼/연산·출처를 확인한다. chart는 PNG, 실제 spec bins, 출처와 입력값을 확인한다. 설명 요청은 관련 단어를 포함하면서 도구 실행/차트 생성 없이 답했는지 검사하고 실제 응답도 검토한다. 단어 검사는 일반적인 답변 관련성 평가를 대신하지 않는다.

## 확인된 문제

### 조건 하나만 해제했는데 전체 범위로 돌아감

1. `segment='blue' AND score>=15`의 score 평균을 요청 → 20.
2. “score 조건만 제거하고 segment 조건은 유지해서 score 평균” 요청.
3. 기대값은 blue 그룹의 **15**지만 실제로 전체 평균 **15.2**를 답하고 완료했다.

`intent_scope.py:132`의 부분 해제 패턴은 `조건만 제거`를 인식하지 못했고, 참조 표현 목록도 이 요청의 `유지`를 인식하지 못했다. 따라서 부분 변경이 아니라 새 조건 없는 분석으로 처리됐다. 모델 호출0회인 실패여서 모델만 교체해 해결할 수 있는 문제가 아니다.

### 설명 질문이 분석 맥락을 오염시킴

1. blue 그룹 평균을 구함.
2. “분석은 잠시 멈추고 히스토그램과 막대그래프 차이만 설명, 계산/생성 금지” 요청.
3. 설명 대신 분석 대상·조건을 확정할 수 없다는 차단 답변.
4. “아까 같은 그룹으로 돌아가 최댓값” 요청에도 OR 조건·조인 관계를 확정할 수 없다고 차단.

설명 요청을 분석 실행 의도로 잘못 취급했고, 분석으로 복귀할 때 마지막 정상 분석의 조건을 회복하지 못했다. 확정된 분석 맥락과 일반 설명 대화/미확정 제안을 분리해 보존해야 한다.

### 다른 데이터로 바꾼 후 이전 조건·출처가 다시 적용됨

1. A 데이터 blue 그룹 평균15.
2. “B 데이터로 바꿔 평균, 앞의 조건은 적용하지 마.” 기대값200 → 실제 B의 blue 그룹 평균250.
3. “그 데이터에서 blue 평균?” 기대값 B의250 → 실제 A의 blue 평균15.

출처 변경과 조건 해제를 하나의 맥락 변경으로 처리하지 못했다. `앞의 조건은 적용하지 마`는 reset 패턴에 없고, `그 데이터`는 후속 참조 패턴에 없다. `recovery.py:934` 부근의 후속 요청 연결도 제한된 표현 목록을 사용한다. UI에서 선택한 dataset과 자연어에서 방금 확정한 분석 출처의 우선순위를 명확히 해야 한다.

## 성공 여부를 따로 확인하는 항목

- “그중 최댓값” → “같은 그룹의 최솟값” → 다른 측정 컬럼 → 조건 해제.
- 저장소를 닫고 같은 대화를 다시 열어 후속 질문.
- 첫 히스토그램5 bins → “구간 수만10개로, 나머지는 유지”.
- 별도 대화의 B 데이터 분석 후 첫 대화의 A 데이터 분석으로 복귀.
- 요약이 실제 실행된 뒤 8턴 동안 그룹·측정 컬럼·연산을 유지/변경.

요약 여정은 실제 middleware의 trigger를 테스트에서만1200 tokens로 낮춘다(제품 기본6000). 단순히 요약 middleware가 호출된 것이 아니라 `summarization_finished/status=ok/summarized=true`를 확인해야 요약 후 보존 시험으로 인정한다. 따라서 일반 운영에서 긴 대화 전체가 검증됐다는 의미는 아니다.

## 요약 이후 실행 관찰

첫 요약 여정에서는 실제 요약 완료 이벤트14회가 확인됐다. 8턴 중7번째 “같은 그룹에서 score 평균으로 다시 돌아가줘”가 `missing_evidence`로 미완료였다. 이때 `segment=blue`, 연산AVG, 지표score는 상태에 남아 있었다. 따라서 이를 조건 자체가 잊힌 증거로 단정하지 않는다. 저장된 맥락을 실제 실행/결과로 연결하지 못한 실패이며, 반복 요약의 비용과 실행 예산도 함께 점검해야 한다. 낮춘 trigger의 stress 결과이므로 제품 기본 설정의 긴 대화 성능과 구분한다.

## 공통 보강 요구

1. **확정 분석 맥락**을 출처/snapshot·모집단 조건·지표/연산·그룹·차트·참조 artifact·미완료 목표로 저장한다.
2. 매 턴에서 유지/교체/추가/해제할 필드를 구분하고, 지정하지 않은 필드를 임의로 초기화하거나 오래된 출처로 되돌리지 않는다.
3. 설명·잡담으로 잠시 전환하면 분석을 실행하지 않고 마지막 정상 분석 맥락을 보관한다. 복귀 시 그것을 사용한다.
4. 자연어로 확정한 데이터 전환, UI 선택, 직전 결과의 참조 우선순위를 명시한다. 여러 후보가 실제로 동등하면 확인 질문을 하고 추측하지 않는다.
5. 대화 원문으로 정한 기대 맥락과 실행 source/filter/metric/chart를 독립 검증한다. 답변이 그럴듯해도 다른 출처·조건이면 실패다.

## 범위와 한계

합성 로컬 데이터이며 warehouse SQL은0회다. actual 모델이 연결됐지만 deterministic 경로의 턴은 모델0회일 수 있다. 이번 요청에서는 production 수정·웹 UI 실행·실제 대규모 데이터 로딩을 하지 않았다. 기존 memory/scope/replacement 계약25개가 통과했지만, 위 실제 대화 조합 실패를 상쇄하지 않는다. 실패를 수정한 뒤 고정 회귀와 새로운 표현/스키마의 held-out 여정을 모두 검사해야 한다.
