# 대규모 보유 데이터의 최신행 선택 — 2026-09-29

기존 누적 변경은 `6a419a99c054dcf9439634f0d2351e15799d54c9`로 push했고 원격 SHA 일치를 확인했다. 이어서 최신행 분포의 대규모 로컬 처리 병목을 수정했다. **범용 GO 판정은 아직 유지할 수 없다(NO-GO).**

## 수정한 경로

기존 도구는 필요한 컬럼이라도 모든 입력 행을 pandas로 읽고 복사·정렬했다. 이제 영속 저장된 20,000행 초과 입력은 필요한 컬럼을 Arrow 배치로 읽어 DuckDB에서 최신행을 선택한다. pandas에는 검증된 최신행 결과만 전달한다. 원본 파일과 선택 기준, snapshot, 부모 계보는 유지한다.

- SQL 실행 메모리 설정 128MB, 임시 디스크 512MB, 실행 중단 타이머 30초.
- 결과 최대 100,000행 / Arrow 결과 64MiB. 한도를 넘으면 미완료로 반환하며 표본·잘린 결과를 전체 분포로 발표하지 않는다.
- `DENSE_RANK`로 최신 정렬값 동률을 남겨 검출한다. 임의의 한 행을 선택하지 않는다.
- 원본의 키·정렬·분포 컬럼 전체에서 NULL을 확인한다. 동률·결측·지원하지 않는 자료형은 확인을 요청한다.
- 대규모 경로의 정렬 컬럼은 저장된 수치 또는 날짜/시각 자료형을 지원한다. 문자열 날짜의 임의 변환은 하지 않는다. 20,000행 이하의 기존 처리 경로는 유지한다.
- SQL은 내부에서 실제 컬럼 이름을 인용해 구성하며 외부 접근을 비활성화한다. 원격 warehouse SQL은 실행하지 않는다.

128MB는 DuckDB 실행 설정이며 전체 Python 프로세스의 메모리 상한은 아니다. 최종 pandas 변환·차트와 런타임 비용은 별도다. 타이머는 DuckDB 중단 요청이며 프로세스 전체를 강제 종료하는 격리 장치는 아니다.

## 독립 평가

외부 fixture recipe로 **100만 행, 1만 키, 키마다 100개 기록, 불필요한 512바이트 컬럼**을 생성했다. 생성과 검증은 별도 프로세스로 분리했다. 검증 프로세스는 production graph에 자연어 요청을 제출하며, 원본의 전체 pandas 읽기/컬럼 projection을 시도하면 실패하도록 감시했다.
