# 목표에 진전이 없는 탐색 반복의 재계획 — 2026-09-27

도구가 성공했어도 사용자 목표가 해결된 것은 아니다. 같은 자료/스키마/도구 설명을 계속 읽는 경로에서 기존에는 모델 호출 10회 한도까지 소모했다. 이제 동일 입력·동일 관찰이 반복되면 검증된 작업과 남은 목표를 분리해 모델에 알리고, 추가 동일 호출을 실행 전에 차단한다. 제한된 재계획 기회에도 반복하면 `discovery_stalled`로 종료한다.

## 구현 계약

- 읽기 전용 탐색 도구에만 적용한다. 원격 query 실행이나 승인 장부는 변경하지 않는다.
- 도구 입력, 관찰, 데이터 metadata/선택/참고 schema/완료 근거의 fingerprint를 비교한다. 스키마나 coverage, 데이터 선택, 결과 근거가 바뀌면 재확인을 허용한다. 비교 과정에서 DataFrame을 복원하거나 원격 SQL을 실행하지 않는다.
- 완료 계약에서 실제 검증된 목표와 미완료 목표를 구한다. 미완료 목표에 관련된 도구도 실제 등록 allowlist 안에서 제시한다. 원래 필터·모집단·원본 보존과 완료 근거 검증은 그대로 적용한다.
- 반복 탐색 기록과 차단 결정은 요청별 체크포인트에 보존한다. 재시작은 한도를 초기화하지 않는다. 새로운 요청은 이전 요청의 반복 기록을 물려받지 않는다.
- 원래 모델/도구/시간 한도를 확대하지 않는다. 새 검증 근거 없이 탐색을 반복하는 것과 실제 데이터/스키마 변화를 구분한다. 진단 로그에는 관찰 원문 대신 hash와 부족한 목표 이름을 남긴다.
- 화면에는 같은 정보 조회가 반복되어 남은 분석 목표에 맞게 계획을 바꾸고 있음을 표시한다. 이미 만든 평균/차트 등을 완료되지 않은 작업 때문에 다시 실행하지 않도록 한다.

## 검증

신규 회귀 6개: 중복 조회 실행 차단 후 계산, 평균 완료 후 차트만 재계획, 달라진 관찰/인자/schema 허용, 재시작 후 기록 보존, 원격·실패 관찰 제외 및 등록 도구 제한, coverage 변경과 새 요청의 상태 분리.

기존 완고한 반복 대역 모델은 10회 호출에서 종료하던 테스트를 **4회 호출·실제 탐색 2회** 안에서 종료하도록 보강했다. 모델이 다른 유효한 계산을 선택하는 별도 여정은 실제 정답 9.0까지 완료한다. 계산+차트 테스트에서는 평균을 정확히 한 번 실행하고, 아직 부족한 chart만 남은 목표로 전달해 PNG를 생성한다.

전체 로컬 검사: application **358/358**, migration **133/133**, reference/Level3 **217/217**(58 figures), compileall·diff check PASS. 추가 coverage 테스트의 최초 실패는 테스트가 영속 metadata의 복사본만 수정한 문제였으며, 실제 임시 저장소를 수정하도록 고친 뒤 통과했다. 정답/허용 여부 assertion은 유지했다.

- 미완료 `compound`: 실제 차트 생성 후 평균 계산 전에 모델 API가 APITimeoutError를 냈다. 2회 재시도까지 실패해 156.738초에 미완료로 반환했다. raw digest는 유지됐고 차트 1개는 보존됐다. 이미 완료한 것으로 답하지 않았다. 모델 tracker는 성공/실패를 포함해 실제 호출 5회를 기록하지만 checkpoint의 `model_calls=2`는 아직 sync되지 않은 성공 호출만이므로 둘을 혼동하지 않는다. 이후 평가 출력은 별도 model recovery 장부와 실패 이벤트도 함께 저장하도록 보강했다.
- 이 검사는 신규 Databricks warehouse SQL을 실행하지 않는다. 이 소규모 결과가 임의 분석 성능, 전체 GO 또는 Codex/Claude Code 동등성을 뜻하지 않는다.
