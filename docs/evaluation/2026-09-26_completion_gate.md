# 완료 계약·복구 개선 및 GO 검증 · 2026-09-26

판정 범위는 로컬 단일 사용자다. 별도 서버 배포는 사용자 지시에 따라 제외한다. 이번 변경의 구현 완료와 전체 agent의 GO는 구분한다.

## 완료한 변경

- 15개 분석 기능의 요청 플래그·검증된 근거·복구 도구·결과 표시를 `completion.py`의 공통 계약으로 묶었다. 조기 완료, 최종 종료, 결과 표시와 부족한 근거 안내가 같은 등록부를 사용한다. 도구 실행/Observation 채택의 모든 분기를 이 등록부로 옮긴 것은 아니다.
- 데이터 로딩/미리보기 성공이 함께 요청한 차트·통계의 미완료를 건너뛰지 못하게 했다. 결과 표시기가 비어 있거나 실패하면 모델의 완료 주장으로 대체하지 않는다.
- 실제 웹에서 원본 10,000행과 과거 부분 데이터 4,442행이 공존할 때 차트 선택이 모호해지고 모델 시간 초과로 이어지는 경로를 발견했다. 요청한 로딩 행 수·선택한 dataset을 우선하며, LIMIT보다 적게 반환된 보호 원본과 그 부분 파생 결과를 구분한다. 대규모 전체 히스토그램의 기존 집계·projection 경로는 유지한다.
- 모델 노드 시간 초과 후 저장된 계산 결과를 유지한 채 안전한 로컬 차트 실행으로 재개한다. SQL 승인 규칙이나 모델 호출 예산을 초기화하지 않는다.
- 실제 도구 호출 전에 JSON Schema를 검사한다. 잘못된 인자의 경로와 enum/type/범위 등 수리 가능한 정보를 반환하며, 데이터 값과 예외 원문은 진단에 복사하지 않는다.
- 원본 스키마에 컬럼이 존재한다는 이유만으로 그 컬럼을 실제 계산한 것으로 인정하던 검사를 보강했다. 분석 대상이 스키마에 연결되지 않은 경우 모델이 임의 선택한 모집단의 숫자를 결과로 채택하지 않는다. 이런 경우는 확인 질문이며 분석 성공으로 채점하지 않는다.

## 실제 웹 증거

기존 승인 대화 `b6f376d1-9398-4d31-8581-f744db786861`에서 다음 요청을 실행했다.

> 현재 로딩된 10,000행 표본에서 age 평균을 계산하고 age 히스토그램도 보여줘.

초기 실행은 평균 계산 뒤 로컬 Ollama ReadTimeout(60.008초, 오류 ID `81e17a2c18ac`)으로 중단됐다. 수정 후 **동일 실패 체크포인트의 미완료 분석 재개 버튼**으로 7.755초에 완료했다. 화면에 평균 **40.931**, **10,000개 값·20 bins 히스토그램**이 동시에 표시되는 것을 확인했다. `completion_checked`의 필수 산출물은 `chart`, `calculation`, 미완료 산출물은 빈 목록이다. 재개에서 새 모델 호출 0회다.

승인 장부는 기존 `completed` 1건 그대로이며 새 Databricks SQL 실행은 0회다. 보호 원본 Parquet SHA256은 `7c4a1c20588261932629087d091d43e1ad2d80f4e36cb3d1acb20eb8462fe10d`로 유지됐다.

## 평가 방법과 한계

200개 참고 문항 중 독립 oracle이 있는 87개를 전체 선택했다. provider는 Databricks Qwen3 Next 80B이며 원격 SQL executor는 연결하지 않고 공개/합성 fixture를 사용한다. 모델이 구성됐어도 controller가 도구를 직접 완료한 문항은 모델 호출 0회로 별도 집계한다. 이 평가는 실제 웹·실 DB 신규 적재·공식 Spider 전체 점수 또는 DeepEval 답변 심사 점수를 대신하지 않는다.

첫 실행은 **82/87 PASS, 4 NOT_COMPLETE, 1 FAIL**이었다. L1_030은 이전 마케팅 결과의 성공 건수 54 대신 다른 결과 컬럼의 건수 270을 반환했다. 이 오답을 정상 결과처럼 채택하는 경로가 출시 차단 결함이며, 스키마에 연결되지 않은 분석 대상의 수치는 이후 변경에서 차단했다. 수정 전 결과를 최종 빌드 점수로 제시하지 않는다.

잘못된 dataset ID를 최초 1회 주입한 별도 복구 검사에서는 자동 로컬 대체 실행을 끈 상태에서 실제 모델이 2회 호출 후 평균 9.0을 정확히 계산했다(3.504초). 원본 불변, 원격 조회 0회. 이 한 건은 범용 자율성 점수가 아니다.

재현 명령:

```bash
.telly_runtime/v1-venv/bin/python scripts/evaluate_analysis_agent.py --live-model --provider databricks --include-final-output --output /tmp/teleai-evaluation/report.json
.telly_runtime/v1-venv/bin/python scripts/evaluate_completion_repair.py --provider databricks --output /tmp/teleai-repair.json
```

Databricks provider는 모델 토큰 과금이 발생한다. SQL 데이터 조회는 실행하지 않는다. 원문·정답·oracle은 이번 실패를 맞추기 위해 변경하지 않았다.

## 남은 출시 게이트

1. 스키마에 직접 연결되지 않는 업무 표현을 필요한 근거 탐색·확인 질문·후속 답변으로 해결하는 다중 턴 여정. 안전하게 차단하는 것만으로 완료 성공률을 높였다고 주장하지 않는다.
2. 공식 Spider 결합 평가의 SQL 의미/방언·기준일·조인 관계 문제. 앞선 local009/local358 실패가 이번 완료 계약 변경으로 해결됐다는 증거는 없다.
3. 신규 적재를 포함한 최종 빌드의 실 웹 승인 여정과 대규모 전체 데이터 전송·메모리·SQL 집계 실측. 기존 표본 재사용 성공과 구분한다.
4. 나머지 113개 미채점 문항, 독립 held-out 여정, 명시적 성공률·지연 기준. 계약 테스트 수를 자율성 또는 출시 점수로 대체하지 않는다.

## 최종 판정

**전체 자율 분석 agent 정식 출시는 NO-GO를 유지한다.** 채점 가능한 동일 87문항 재실행은 **78 PASS / 9 NOT_COMPLETE / 0 FAIL = 89.7% 완료**다. 미채점 113개를 통과로 포함하지 않는다. 의미 미확정 질문을 수치로 출력하지 않도록 차단하면서 일부 이전 성공도 확인 질문으로 바뀌었다. 안전한 차단은 정확한 분석 완료와 다른 결과다. 수정 전 82/87을 최신 성공률로 인용하지 않는다.

미완료: `L1_023`, `L1_024`, `L1_025`, `L1_026`, `L1_028`, `L1_029`, `L1_030`, `L1_047`, `L2_012`. 모델 비결정성과 도구 선택 실패도 포함하므로 전부 같은 원인이라고 단정하지 않는다. 특히 업무 의미/컬럼 연결·생존/가입 같은 값의 의미, 필터된 그룹 빈도와 복합 계산의 완료를 개선해야 한다. 기대 정답에 맞춰 제품에 테이블명·컬럼명·조건값을 고정하지 않는다.

최종 앱 unittest **284/284**, migration **133/133**, 전체 참고/Level3 **217/217** 통과. 원본 유실·승인 우회 여부는 회귀와 이번 웹 여정에서 확인한 범위이며, 모든 데이터에 대한 보증이 아니다. 결과 누락, 잘못된 컬럼 계산, 미확정 모집단, 잘못된 enum, 원본/부분 결과 공존, 재시작 후 복합 요청 재개를 회귀로 포함했다.

상세 상태·지연·실제 모델 호출 수는 [평가 결과 JSON](2026-09-26_completion_scores.json)에 보존한다. 전체 raw 평가 보고서는 로컬 `/tmp/teleai_completion_final_live/report.json`이며 JSON에는 재현·대조용 SHA256을 저장했다. 이번 최종 검사는 공식 Spider나 DeepEval를 새로 실행한 점수가 아니다.
