## 평가별 근거와 제한

- [200문항 결과](reference_200.json): 실제 모델 호출 총14회. 97 PASS 중 모델 없이 결정적 경로로 통과한 항목도 포함한다. 103개에는 독립 비교 oracle이 없어 모델을 호출하지 않았다. UNGRADED는 구현 불가/실패/성공 중 어느 하나로 추측하지 않는다.
- [자연어 여정](language.json): 평균·중앙값·최대값·제외·조건 유지/연산 변경·복합 차트를 검사했다. synthetic 데이터이며 warehouse 접속 검사가 아니다.
- [장애/대화](recovery.json): 오류 종류별 실제 모델 회복3건과 후속 대화1건. 구조적 구제 경로를 끈 진단 모드이므로 일반 production 경로의 성공률과 합산하지 않는다. 각 복구는 고정4행 fixture 한 번이며, 모든 오류 상황의90% 복구율을 입증하지 않는다.

local002/003/004/008은 `unverified_join_relationship`로 제안되지 않았다. 각각 보존된 마지막 SQL 초안은 SQLite에서 실행 가능했으나 공식 정답과는 불일치했다. local007은 제안·실행 가능했지만 공식 결과는 오답이다. 따라서 이번에는 차단기를 풀어도 정답이 되지 않는다. 관계 검증과 다단계 의미 계획을 모두 보강해야 한다.

## DeepEval: 점수 자체도 검증해야 함

설치 버전4.2.3, 로컬 judge `gemma4:e4b`를 사용했다.

[도구 검사](deepeval_tools.json)의 L1_016은 `aggregate_dataset`을 기대했지만 실제로 `local_analysis_sql`로 정답을 계산했다. 제품 독립 oracle은 PASS지만 exact tool matching은0점이다. 이 점수를 그대로 agent 능력90%라고 해석하지 않는다. 허용 가능한 대체 경로를 반영한 평가 계약이 필요하다.

[Judge 대조군](judge_calibration.json)은 정상 답변1개와 목표 누락·잘못된 수치·잘못된 bins 답변3개를 사용했다. 오답3개는 모두0점으로 잡았지만, 정상 한국어 답변은 “A=1.5; B=3.5”와 형식이 다르다는 이유로0.6을 줬다. 평가 지침은 형식을 강제하지 말라고 명시했으므로 judge 오판이다. 4개 대조군은 보정의 시작일 뿐 신뢰도 인증이 아니다.

실제 복합 EDA 응답4개의 최초 GEval 실행은 모두 `RetryError`로 미채점이었다([최초 결과](deepeval_numeric.json)). 오류의 중첩 예외 타입을 보존하도록 평가 harness를 보강한 뒤 그룹 평균 누락1건만 진단 재실행했고, 이번에는0.0으로 올바르게 채점됐다([재확인](deepeval_diagnostic.json)). 오류가 재현되지 않아 최초 실패의 내부 원인은 확인하지 못했다. 최초4건 실패를 재확인1건 성공으로 덮어쓰지 않는다. 점수가 없는 항목은0점이나 통과가 아닌 **채점 실패**로 처리한다. 이 보조 점수가 수치/차트 독립 판정을 뒤집지 않는다.
