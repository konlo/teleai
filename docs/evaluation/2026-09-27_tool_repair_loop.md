# 문제 해결 agent: 도구 실패 후 계획 변경 — 2026-09-27

모델이 실패한 도구를 다시 선택하면 같은 호출을 실제로 두 번 실행한 뒤 대화를 중단하던 경로를 바꿨다. 이제 실패 원인에 맞는 탐색 지침을 제공하고, 변경 없는 실패 호출은 실행 전에 차단해 대체 계획을 선택할 기회를 한정적으로 제공한다. 모델이 계속 같은 호출을 고집하면 중단한다. 이 완료 범위는 도구 복구이며 전체 범용 GO는 아니다.

## 실행 계약

1. 로딩되지 않은 ID, 잘못된 인자/SQL, 메모리 한도, 로컬 도구 불가를 구분한다. 후보 도구는 실제 등록 allowlist에서만 제시한다. 반환된 임의 오류 메시지는 system 지시로 승격하지 않는다.
2. 실패 호출·진단 제공·차단된 반복을 요청별 체크포인트에 남긴다. 새 요청에서는 초기화하지만 재시작/재개는 초기화하지 않는다. 원문 인자나 행 대신 실패 signature hash로 진단 이벤트를 연결한다.
3. 동일한 실패 호출을 다시 실행하지 않고 모델이 도구 schema/자료 상태를 확인해 인자를 수정하거나 다른 도구를 선택하게 한다. 재계획 후에도 반복하면 기존 전역 호출/시간/도구 한도와 제한된 복구 기회 안에서 종료한다. 정상 metadata 재확인과 원격 승인 흐름은 별도로 유지한다.
4. 로컬 도구의 실제 TimeoutError는 관찰 가능한 `local_tool_timeout`으로 반환한다. SQL 승인 실행기를 이 재시도 경로에 넣지 않는다. 알려지지 않은 프로그램 예외를 임의의 성공이나 일시 오류로 바꾸지 않는다.
5. 대체 도구도 원래 필터·출처·집계·모집단 검증을 통과해야 한다. 진단/계획만으로 완료할 수 없으며 실제 계산/차트 근거가 필요하다. 원본과 이미 완료된 결과를 유지한다.
6. 화면 진행 문구로 실패 진단, 동일 호출 차단, 대체 계획 검토를 표시한다. 내부 복구 지침은 사용자 대화 원문에 섞지 않는다.

## 재현과 실제 모델 검증

같은 합성 집계 도구 장애를 두 번 선택하도록 주입한 [수정 전](2026-09-27_tool_repair_baseline.json)은 대체 방법을 모델에 물어보기 전에 종료했다. 수정 후 [최초 확인](2026-09-27_tool_repair_initial.json)은 두 번째 실제 실행을 막고 실모델이 local_analysis_sql을 선택해 평균 9.0을 계산했다. 실패·기대값·원본 fixture는 그대로 유지했다.

고정 로컬 자동 계획/구제 경로를 비활성화한 [실제 모델 여정](2026-09-27_tool_repair_live.json):

6여정·7턴 PASS, 실제 모델 추론 13회. 일부 첫 호출/반복 호출은 장애 주입이며 모델 호출 수에 포함시키지 않았다. 차트는 실제 PNG signature와 존재를 검사했다. 이 여정의 차트 평가는 통계 빈도 전체의 독립 검증까지 수행하지 않으므로 별도 고정 자연어 평가의 차트 grader와 구분한다.

추가로 최종 timeout 처리 코드에서 [실제 TimeoutError → 실모델 대체 도구 선택](2026-09-27_tool_repair_timeout.json)을 별도로 실행했다. 공급자 모델은 실제이지만 도구 장애는 합성 주입이다. 실제 Databricks warehouse 실행기를 연결하지 않았으며 신규 warehouse SQL은 없다.

## 자동 회귀와 한계

- 새 회귀 6개: 중복 실행 방지/대체 완료, 요청 간 초기화와 요청 내 제한, 필터 누락 우회 차단, 재시작 후 계획 보존, 비신뢰 오류 문구 및 도구 allowlist, 실제 로컬 TimeoutError 변환. 진행 callback과 원본 digest도 검사한다.
- 기존 반복 실패 테스트는 실행 2회 후 종료에서 실제 실행 1회·제한된 재계획 후 종료로 기대값을 수정했다. 진단 테스트의 대역 모델은 마지막 메시지가 반드시 ToolMessage라는 가정을 제거하고 실제 가장 최근 도구 관찰을 읽도록 했다. 결과 정답/원격 미실행/오류 로그 assertion은 유지했다. 최초 migration와 A3_014 실패는 이 fixture 가정 때문이었다.
- 최종 application 352/352, migration 133/133, reference/Level3 217/217(58 figures), compileall·diff check PASS.

7개 실제 모델 여정(두 보고서, 8턴)이 통과했지만 임의 문제 해결 성능이나 Codex/Claude Code 동등성을 뜻하지 않는다. 복잡한 SQL/복합 조건 계획, 미채점 103문항과 judge calibration, 실제 승인형 대규모 원격 적재, 격리 코드 실행 및 장기 장애 검증은 남는다. 범용 GO 보류.
