# Databricks 자동 읽기 전용 실행 정책 검증

2026-09-28. 사용자가 제품의 매 SQL 필수 승인을 제거하도록 요청했다. 기본값은 자동 조회이며 `TELLY_REQUIRE_REMOTE_APPROVAL=true`에서만 기존 수동 모드를 사용한다.

## 변경

- graph의 승인 interrupt와 도구 내부 gate 양쪽에 같은 정책을 적용했다. 영속 장부에서 `auto_authorized`로 실행 권한을 부여하며 사용자 승인 메시지를 생성하지 않는다. 실행 이후에는 기존 receipt를 보존한다.
- SQL 검증, 정확한 query/source/connection 결합, 중복 제출 차단, 실행 예산과 데이터 원본 보존은 유지한다. 거절·취소·실패·제출 불명 상태를 자동 권한 부여로 되살리지 않는다.
- 기존 승인 대기 checkpoint를 같은 그래프 노드에서 자동 재개한다. 화면에서도 재질문 없이 재개하고, 새로운 사용자 요청이 들어오면 기존 대기 제안을 무효화한다.
- prompt, 도구 설명/검색, metadata 계획 안내, 내장 분석 skill, UI 및 현재 출시 기준의 충돌하는 승인 지시를 변경했다. 실제 반환 결과로 답하며 나중에 알려주겠다는 응답을 완료로 취급하지 않는다.

| 로컬 앱 재시작 | health 200 | 127.0.0.1:8502, 자동 정책 확인, 실행 중 대화 중단 없음 |
| compileall / git diff --check | PASS | 변경 코드 및 whitespace |

자동 실행 테스트는 모델 호출→조회→목록 출력, 0행, timeout/중복 재실행 차단, 수동 대기에서 자동 모드 전환, 도구 내부 대기 복구, 거절 및 연결 변경 차단, 변경 SQL 차단, 히스토그램 생성과 추가 원격 조회 없는 재사용, UI 재실행을 포함한다.

확대 검사 중 발견된 이전 승인 기본값 가정은 수동 정책을 명시하도록 수정했다. 오프라인 평가기가 원격 요청을 받은 경우는 자동 모드에서 `FAIL/blocked`와 실제 원격 실행 0회를 요구한다. 실행 receipt를 누락한 테스트 대역은 실제 executor와 동일한 dataset metadata를 반환하도록 고쳤다.

## 제한

실제 연결 검사는 SELECT 1만 실행했다. 업무 테이블·대규모 적재를 이번에 다시 검증한 것은 아니다. 실제 모델 평가는 합성 목록 조회 1개이며 전체 agent 완성도나 범용 GO를 뜻하지 않는다. 기존 최신행 선택·복합 분석·대화 맥락의 미완료 과제는 별도 유지한다. 커밋·push는 이번 변경에서 수행하지 않았다.
