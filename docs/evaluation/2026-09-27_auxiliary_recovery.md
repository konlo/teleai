# 대화 요약·승인 판독의 공통 모델 복구 — 2026-09-27

이번 완료 범위는 모델 실패가 승인이나 대화 상태를 손상시키는 경로의 보강이다. 범용 자율 분석 agent의 전체 출시 판정은 **NO-GO**를 유지한다.

## 원인과 수정

승인 대기 중의 자연어 메시지는 공통 모델 복구를 거치지 않았다. JSON 판독 실패도 요청 변경으로 처리해 아직 유효한 승인을 취소할 수 있었다. 이제 명확한 `change` 분류만 기존 승인을 무효화한다. 불명확한 말, 잘못된 응답, 인증 오류와 일시적 장애는 정확한 승인 SQL·체크포인트를 유지한다. 명시적 승인·취소 버튼/문구는 모델 판독과 독립적이다.

승인 판독 호출은 부모 요청의 공통 횟수·시간 예산을 사용한다. 유효한 판독은 요청·승인·메시지의 해시에 연결해 재시작 후 같은 질문에도 재사용한다. 원문은 캐시나 진단 로그에 저장하지 않는다. 판독 실패 시 오류 ID·단계·유형을, 잘못된 JSON은 별도 이벤트로 기록한다.

설치된 LangChain의 요약 미들웨어는 내부적으로 `model.with_retry()`를 사용했다. 이 숨은 재시도를 제거하고 주 분석·의미 해석과 동일한 영속 실패/재시도/cooldown 장부로 통합했다. 요약과 승인 판독은 마지막 분석 호출 한 번을 남긴다. 401·프로그래밍 오류는 자동 재시도하지 않는다. SQL 실행기를 재시도 대상으로 감싸지 않는다. 기존 장부의 schema 업그레이드는 실패 횟수와 예산을 보존하고 SQLite 쓰기 잠금으로 직렬화한다.

## 검증과 실패 기록

- 새 장애/상태 회귀 11개: 판독 429 복구, 401·잘못된 JSON·모호한 말의 승인 보존, 명시적 승인 후 정확히 1회 실행, 재시작 cooldown·공통 예산, 요약의 숨은 재시도 제거·원문 보존·graph 재시작, 이전 장부 업그레이드.
- 기존 migration 두 테스트는 잘못된 자유문 응답을 요청 변경으로 가정했다. 명시적 `change` fixture로 바꾸되 승인 무효화·복제 대화 격리·새 요청 완료 assertion을 유지했다.
- 실제 Databricks 모델 serving의 최초 두 실행은 승인 필요성 질문을 `uncertain`으로 분류했다. [최초 실패](2026-09-27_auxiliary_live.json)와 [원인 확인](2026-09-27_auxiliary_live_recheck.json)을 보존했다. 응답 JSON은 유효했으므로 형식 문제가 아니라 승인 정책 질문의 분류 문제였다. 판독 prompt에서 정책/필요성 질문도 상태 질문임을 명확히 하고 불명확한 발화와 구분했다.
- 질문·기대값을 유지한 [최종 실제 모델 검사](2026-09-27_auxiliary_live_verified.json)는 상태 질문 2개, 모호한 말 1개, 동일 질문 캐시 1개, 긴 대화 요약 1개 모두 PASS. 요약 후 표시용 원문이 보존됐다. 모든 SQL 실행 0회. 이는 5개의 통합 검사이며 범용 자연어 정확도나 실제 공급자 장애 복구율이 아니다.
- [실제 모델 관계 탐색 여정](2026-09-27_auxiliary_relationship.json): 고정 공개 합성 SQLite fixture에서 관계 탐색→SQL 승인 제안→테스트 승인→집계 결과 3 검증 PASS. 모델 4회, 7.320초, 승인 전 실행 0회·승인 후 1회. 기존 raw 선택·digest 보존. Databricks warehouse에는 연결하지 않았다.
- [실제 웹](2026-09-27_auxiliary_web.json): 이전 `age < 60` 조건의 후속 중위수 39.0, 독립 Parquet 정답 일치, 3.619초·모델 2회. 보호 raw SHA256·선택 ID·completed 승인 1건 유지, 새 warehouse SQL 0회.
