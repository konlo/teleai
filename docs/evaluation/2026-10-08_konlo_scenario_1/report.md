## 근본 문제와 수정 우선순위

1. **마지막 성공 상태와 실행 중/실패 상태를 분리해야 합니다.** 8번 실패 후9~16번은 `previous_analysis needs a verified completed subject`로 차단됐습니다. `core/analysis_agent/conversation_context.py:19`의 prior_analysis는 exhausted 상태에서 보존된 confirmed_analysis를 선택하지 않습니다. 파일 보존과 대화 맥락 복구는 별개입니다.
2. **실행 계획이 실제 도구 호출로 이어지도록 해야 합니다.** 8번은 올바른 조건을 해석했지만 planner3회가 tool_call_count0으로 종료됐고 agent는 새 경로를 찾지 못했습니다. 25번은 요약97.1초와 계획64.8초 등에 예산을 써 실행하지 못했습니다. planner 도구 탐색/실행 의무, 무진전 감지, 요약 예산과 실행 예산 분리가 필요합니다. 이번 두 건의 최종 오류는 ReadTimeout/DB400이 아니라 model_time_budget입니다.
3. **차트 종류·축 변경은 모집단 변경과 구분해야 합니다.** 17·18번은208699명 조건을750000명으로 바꿔 완료됐습니다. `core/analysis_agent/population_audit.py:36`은 previous_analysis로 분류됐을 때만 이전 필터를 전달합니다. 출처 표기 방식이 달라졌다는 이유로 동일 테이블의 필터를 지우면 안 됩니다. 완료 검증도 보존해야 할 모집단과 실제 결과를 비교해야 합니다.
4. **존재하지 않는 명시 테이블도 요청의 출처로 보존해야 합니다.** 27번 raw 요청을 import로 대체했고28번도 잘못된 출처를 이어받았습니다. `core/analysis_agent/source_references.py:11`은 이미 알려진 catalog identity만 검출하므로 없는 이름은 출처 검증에서 빠집니다. LLM이 추출한 원문 table literal을 독립 catalog조회로 확인하고 없으면 정확히 안내하거나 명시적인 선택을 받아야 합니다.
5. **누적 차트는 별도 구현·검증이 필요합니다.** 12·13번은 이전 분석 차단으로 실제 누적 그림을 생성하지 못했습니다. 범례 지원만으로 누적 요청의 성공을 선언할 수 없습니다. 복구 수정 후 실제 bin별 누적 높이·색상·범례를 재평가해야 합니다.

현재는 단독 기본 조회/명시 전체 산점도는 동작하지만 실패 후 자율 복구와 맥락 유지가 부족합니다. 위 P0 묶음을 통합 수정하고, 이 동일31개를 새 대화에서 최초 제출로 재평가한 뒤 미평가 표현·다른 스키마·Databricks 여정을 확장해야 합니다.
