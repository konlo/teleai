# 고급 분석·대규모 적재 검증 계획

1. 현재 production graph의 통계/조인/시계열 독립 oracle 평가를 재실행한다.
2. 공식 Spider2 Lite의 기존 고정 5문항을 같은 adapter와 실제 Databricks 모델로 재평가한다. SQL은 로컬 benchmark DB만 대상으로 하며 warehouse 조회는 없다. 미제안·오답·채점 불가는 구분한다.
3. 로컬 합성 1,000,000행 저장·cache·변경 격리·재시작·강제 중단 복구의 RSS/시간을 측정한다. 실제 Databricks 적재로 간주하지 않는다.
4. 실제 승인형 적재는 아래 정확한 SQL 1회만, 사용자 승인 이후 별도 검증 대화에 실행한다. 기존 사용자 대화의 선택 원본과 데이터는 교체하지 않는다. 결과의 실제 schema를 cursor metadata에서 취득한다. 100,000행/512MiB 기본 수신 상한과 staging/발행 검사를 적용한다. 전체 테이블이 아닌 제한 결과로 표기한다. 실제 수신 행/bytes·RSS·적재 후 로컬 재사용/차트·원본 보존을 기록한다.

```sql
SELECT * FROM workspace.default.ncr_ride LIMIT 100000
```

정확한 SQL 승인 없이는 4번을 실행하지 않는다. 테이블이 없거나 권한/토큰/용량 제한으로 실패하면 실패 증거를 보존하며 수정한 SQL이나 재조회는 별도 승인 대상으로 남긴다. 범위와 상한을 늘려 통과시키지 않는다.
