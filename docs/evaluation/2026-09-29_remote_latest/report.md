# 원격 최신행 분포 집계 — 2026-09-29

Databricks에서 키별 최신행 선택과 범주 집계를 수행하고 검증된 차트를 반환하는 경로를 구현했다. **실제 750,000행에서 12개 키를 집계해 4행만 전송했으며 독립 SQL 정답과 일치했다.** 전체 범용 agent의 GO 판정은 아직 NO-GO다.

## 구현

관측된 테이블 스키마로 `prepare_remote_latest_distribution`이 SQL을 계획하고, 기존 `query_databricks`의 실행 정책·장부를 통해 실행한다. 같은 SQL의 결과 ID를 도구에 전달해 검증과 차트 생성을 완료한다. 계획 도구가 원격 조회를 직접 우회 실행하지 않는다.

- 하나의 SQL에서 `DENSE_RANK` 최신행, 키별 동률, 전체 결측 수, 전체 행/키/범주 수, 범주 빈도를 계산한다. 최대 52행만 반환한다.
- 검증 행과 빈도 합계가 일치해야 하며 NULL, 최신 시각 동률, 50개 초과 범주, 잘린 결과, 잘못된 조회/출처는 완료로 인정하지 않는다.
- 완료된 실행 장부와 저장 dataset, 정확한 SQL, 차트 계보를 대조한다. 계획되지 않은 전체 원본 조회를 대체 경로로 허용하지 않는다.
- 기존 원본과 선택 상태를 보존한다. 같은 요청은 재시작 이후에도 검증된 결과를 재사용한다. 명시적 재조회 요청은 새 실행으로 처리한다.
- “현재 로딩된 데이터”로 범위를 한정한 요청을 원격 조회로 확대하지 않는다.
- 오래된 스키마는 0행 조회로 갱신한다. 연결기가 반환하는 Arrow 스키마를 저장해 정수·시각·decimal 타입을 보존한다. 타입이 확인되지 않은 경우 임의의 과거 타입을 붙이지 않는다.

코드에 특정 테이블·컬럼·업무값을 넣지 않았다. 실제 관측된 이름과 자료형을 사용한다.

## 실제 Databricks 검증

검증 요청은 `workspace.default.bank_loan`에서 **job별로 id가 가장 큰 행의 education 분포**다. ID가 실제 발생 시각이라는 가정은 하지 않았다. 명시된 최대 ID 기준을 사용했다.

| 경로 | 결과 | agent 처리 시간 | 내려받은 집계 결과 |
|---|---|---:|---:|
| 현재 스키마로 계획 | PASS | 23.071초 | 4행 |
| 오래된 스키마 → 자동 갱신 → 계획 | PASS | 11.879초 | 4행 |

두 실행 모두 750,000행의 12개 직업 키에서 `secondary=7, tertiary=4, unknown=1`이 나왔다. 별도로 작성한 `ROW_NUMBER` SQL의 정답과 일치했다. 같은 요청 반복 시 추가 warehouse 조회는 0회였다. 실제 PNG도 생성·확인했다.

첫 시도에서는 Databricks catalog가 정수형을 `LONG`으로 반환해 자료형 검증에서 중단됐다. 원격 집계는 실행하지 않았으며 성공으로 세지 않았다. `LONG/SHORT/BYTE` 처리와 회귀를 추가한 뒤 두 실제 여정이 통과했다. `live.json`에 첫 미완료 결과를 보존했다.

이번 실험의 실제 읽기 전용 SQL은 총 **8회**: 첫 스키마 확인 1회, 정상 여정의 스키마/집계/독립 정답 3회, 갱신 여정의 스키마/0행 probe/집계/독립 정답 4회다. 모델은 Databricks 설정이지만 이 명확한 요청은 결정적 도구 경로로 처리해 모델 호출 0회였다. LLM 자유 계획의 일반 성공률로 해석하지 않는다. 두 지연값은 운영 SLO나 성능 향상 비교가 아니다.

## 회귀와 증거

원격 SQL은 DuckDB 변환 실행을 통한 독립 합성 oracle와 실제 Databricks에서 각각 검증했다. 합성 실행을 실제 warehouse 실행 횟수에 포함하지 않았다.

- 원격 계획/실행/차트, 기존 원본 보존, 재시작·반복 재사용, 명시적 재조회.
- 수동 승인 checkpoint의 재개와 자동 실행 정책, 제출 여부 불명 시 재실행 금지.
- NULL·동률·빈 테이블·범주 초과·통계 변조의 잘못된 완료 차단.
- 오래된 스키마 갱신, 이름을 바꾼 컬럼과 인용 식별자, SQL/실행 장부 불일치 차단.
- 0행 Arrow 정수/시각/decimal 스키마 저장 및 잘못된 비어 있지 않은 probe 거부.

실행 결과는 `live_fixed.json`, `live_stale_schema.json`, 이미지 근거는 `live_chart.png`다. 처음 전체 회귀에서 발견한 decimal 타입 관측 누락도 수정했고 최종 검사 결과는 `validation.json`에 기록한다.

## 남은 범위

현재 원격 경로는 명시된 단일 키·정렬 기준의 **범주 빈도**를 지원한다. 자연어 복합키·동률 해소 정책, 최신행 선택 전후 필터의 적용 시점, 연속 수치 히스토그램·맞춤 구간·복합 통계는 별도 과제다. 완전히 알려지지 않은 출처의 탐색도 이번 결과로 검증했다고 주장하지 않는다. 이후 고급 OR/NULL·역할별 조인, 미채점 103개 oracle, DeepEval judge 보정이 필요하다.
