# LLM 판단 → 도구 실행 → 관찰 → 재계획

2026-10-11 변경. 자연어 요청의 `intent_origin=llm` 경로에 적용한다.

1. 모델이 요청과 확정 맥락을 읽어 목표·출처·조건·작업을 선언한다. 독립 원문 검토 및 스키마 근거 검증을 통과해야 실행한다.
2. `action_cycle_v1`은 확정 목표, 미완료/검증 완료 계약, 최근 도구 상태와 원격 receipt, 선택 가능한 실행 후보를 모델에 전달한다. 후보는 조언이며 자동 실행하지 않는다.
3. 모델이 실제 tool call을 선택한다. 후보와 다른 등록 도구를 선택하거나 계약을 탐색할 수 있다. 검색과 `get_analysis_tool_contract`로 확인한 등록 도구는 다음 호출의 메뉴에 추가된다.
4. 실행기는 도구 인자, SQL 읽기 전용·출처·조건, 조회 장부와 원본 보존을 검증한다. 반환된 관찰을 읽은 뒤 **다음 의존 행동은 다시 모델이 선택**한다. 계획 도구가 SQL을 반환해도 코드가 모델의 다음 선택을 조회로 덮어쓰지 않는다.
   조회 이유 문구는 SQL 실행 조건이 아니다. 계획과 같은 출처·정규화된 SQL은 설명 문구나 SQL 서식 차이 때문에 거절하지 않는다. 출처·조건·행 제한·투영이 바뀌면 여전히 거절하며, 원격 장부/승인은 실제 실행하는 SQL과 envelope를 보관한다.
5. 실패 상태·오류 코드로 정한 복구 선택지를 모델에 제공한다. 실행하지 않은 후보의 검증 실패는 실제 요청 실패로 기록하지 않는다. 스키마 `needs_refresh` 뒤 새 관측이 생기면 재검사를 허용한다. 반복 동일 오류, 불확실한 원격 제출, 예산 소진은 계속 차단한다.
   모델이 실제 선택한 호출의 입력/범위 거절은 별도 관찰이다. 실행된 도구 실패와 구분하되 다음 선택의 근거와 이력에 포함한다. 확정된 축·범례·색상·bin·현재 결과 범위는 `execution_constraints`로 전달하며, 지원하지 않는 옵션은 도구 계약을 탐색하거나 다른 도구를 선택한다.
6. 완료는 수치·범위·행 수·실제 차트 artifact 계약이 증명해야 한다. 설명만 한 응답이나 미래 실행 약속을 완료로 취급하지 않는다.

## 기록과 경계

- 진단 로그: `model_action_observation` → `model_action_selected` → 기존 도구/조회/완료 이벤트. 실행 ID로 연결한다.
- 영속 계획 이력: observation ID, 선택 도구·call ID·인자 해시, 관찰한 실패 ID와 미완료 계약을 보관한다. 비공개 사고 과정은 기록하지 않는다.
- 화면 진단 요약의 `관찰·행동 루프`는 관찰·모델 결정 횟수 및 실패/의존 상태 관찰 후 결정 횟수를 표시한다. 결정 횟수에는 tool call이 없는 모델 응답도 포함된다. 이 숫자 자체는 성공률이 아니다.
- 요청 예산/모델 연결이 소진되면 모델이 선택하지 않은 새로운 분석 도구를 코드가 실행해 성공으로 바꾸지 않는다. 이미 실행하여 검증된 결과는 보존한다.
- 목표·참조 해석은 원래 대화 기록을 읽는다. 목표가 검증된 뒤 행동 모델에는 확정 맥락과 현재 요청의 tool-call/receipt 쌍을 전달한다. 이전 턴의 원문·데이터·내부 추론을 매 단계 반복하지 않으며, 원본 기록은 checkpoint에서 보존한다. 현재 목표·필터·출처·관찰을 한도 초과 때문에 조용히 버리지 않는다.
- 명시적인 controller 작업과 `contract_fixture` 테스트 경로는 별도다. 대역 모델의 선택은 자연어 이해 점수나 실제 Azure 운영 증거가 아니다.
- 작업별 독립 범위/DAG, 대규모 연속값 DB bin 집계, 모델 지연·장기 맥락 및 회사 Azure/Windows 종단 평가는 별도 남은 항목이다. 이 변경만으로 GO 또는 범용 자율 문제 해결 완료를 선언하지 않는다.

회귀: `tests/test_model_action_cycle.py`, provider wire 계약과 histogram 재사용 검사.
