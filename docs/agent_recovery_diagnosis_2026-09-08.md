# 실패 후 대안을 실행하지 못하는 agent 구조 진단

## 실제 원인

사용자가 인용한 ‘기술적인 문제’는 진단 코드나 실제 예외 메시지가 아니라 모델이 생성한 모호한 설명이다. 원래 실행의 context_budget_exceeded와, 수정 후 재실행의 dataset_not_loaded를 구분해야 한다. 재실행은 로딩된 DataFrame 없이 recommend_chart_images를 호출해 거절됐으며 PNG 렌더링이나 Databricks 조회에 도달하지 않았다. 따라서 해당 답변을 Databricks 403이나 이미지 엔진 장애로 설명할 근거는 없다.

증거: histogram_failure_recheck.json. 재실행 277.124초, 조회/이미지 생성 성공 없음. 인용된 답변은 후속 ToolOutcomeMiddleware 추가 전 생성되어 대화에 저장된 내용이다. 코드 변경만으로 과거 답변이 수정되지는 않는다.

## 구조적 결함

1. 목표의 완료 조건이 없다. runtime은 graph 종료와 final text를 answered로 취급한다. 사용자 요청의 대상·범위·chart kind와 일치하는 실제 artifact를 검증하지 않는다.
2. 복구 전이가 없다. tools.py의 dataset_not_loaded는 모델에게 안내만 반환한다. 데이터 확인 → 조회 계획 → 승인 대기 → 실행 → 시각화의 필수 전이가 보장되지 않는다. 예외를 관찰로 바꾸는 것은 복구 실행 자체가 아니다.
3. 후속 guard도 실패 안내만 한다. ToolOutcomeMiddleware는 마지막 도구 오류에 대해 최종 문구를 바꾸지만 재계획 노드로 이동시키지 않는다. 마지막 도구만 보므로 실패 후 metadata 성공 또는 no_valid_chart/빈 카드에는 잘못된 성공 답변이 통과할 수 있다.
4. 도구 계약이 대안을 제한한다. recommend_charts는 raw 수치 행에 대해서만 히스토그램을 만들고, 미리 계산한 bin/count를 받는 히스토그램 렌더러는 없다. 대용량 DB 집계 대안은 현재 구현된 기능이 아니다. 추천 도구에는 명시적인 chart kind 인자도 없어 요청한 종류의 산출물 검증이 필요하다.
5. 문맥 관리는 예산 초과를 막는 부분과 목표/증거 보존을 분리하지 못했다. 요약과 과거 모델의 근거 없는 설명을 사실로 취급하지 않도록 완료 증거를 별도로 관리해야 한다. 실제 요약이 어떤 의미 오류를 유발했는지는 이번 정적 진단으로 단정하지 않는다.
6. 테스트는 ID 거절 및 답변 교체를 증명하지만, 사용자가 요청한 이미지가 없을 때 다음 행동으로 진행해야 한다는 계약은 증명하지 않았다. 모델 변경만으로 이 실행 제어 결함이 해결된다고 판단할 근거는 없다.

## 필요한 전환

- 요청별 작업 상태에 목표, 대상, 범위, 기대 산출물, 시도한 전략, 실패 코드와 복구 예산을 보존한다. 기존 checkpoint/asset/approval ledger를 대체하지 않고 연결한다.
- 모델은 가능한 전략을 제안하고 controller는 전제조건·권한·실제 결과를 검증한다. 목표 미달성에서 근거 없이 종료하지 않는다.
- 데이터 미로딩: 보유 자산/저장 스키마 확인 후 최소 조회를 계획하고 제품 승인 카드로 전이한다. 승인 전 조회하지 않는다.
- 데이터가 크면 bin/count 집계와 이를 그대로 렌더링하는 도구를 함께 구현한다. 샘플로 바꿀 때는 모집단 히스토그램인 것처럼 표시하지 않는다.
- 렌더 실패면 동일 데이터/조건을 보존하며 지원하는 다른 렌더 경로를 시도한다. 시도 횟수와 시간을 제한하고 같은 실패를 반복하지 않는다.
- 권한 거절/불명 제출에는 우회·재제출하지 않는다. 원인과 필요한 조치를 명시한다.
- 종료 상태를 목표 달성, 승인 대기, 외부 조건 차단, 복구 예산 소진으로 구분한다. 함수/graph 반환을 목표 달성과 동일시하지 않는다.
- 완료는 적합한 데이터 범위와 실제 PNG/차트 종류/컬럼 연결로 검증한다. ‘확인했다’는 모델 문장은 증거가 아니다.

## 재현과 검증 기준

이번에는 production 코드를 변경하거나 원격 조회를 재실행하지 않았다. 실제 저장 로그와 코드 경로를 읽고 guard를 오프라인 호출했다. recovery_guard_diagnosis.json은 마지막 오류 문구 교체는 작동하지만, 재계획 지시가 없고 metadata 성공/빈 차트 이후에는 차단되지 않음을 기록한다.

필수 후속 평가: 데이터 없는 histogram 요청 → 승인 카드, 승인 → 실제 이미지, 거절 → DB 0회, 권한 거절 → 사실에 근거한 차단 안내, 잘못된 ID → 대안 실행, 빈 카드/metadata만 성공 → 미완료 유지, 재시작 → 동일 작업/승인 복원. 전체 사용자 여정 평가를 통과하기 전 출시 가능으로 표시하지 않는다.
