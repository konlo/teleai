# 전환 전 검증 결과와 후속 작업

대상은 현재 AnalysisSession이다. LangGraph 전환 구현의 통과 보고서가 아니다.

## 사용자 대화의 상태 계약

합성 데이터와 정답은 `tests/fixtures/analysis_acceptance.json`에 분리했다. 전체 원본을 이미 로컬에 보유하므로 아래 네 요청은 모두 DB 조회 없이 계산해야 한다.

| 턴 | 유지 조건 | 변경 조건 | 기대 값 | 허용 실행 |
|---|---|---|---|---|
| 1 | 보유 데이터 출처 | 기간=2026-08, 지표=value 평균 | 40 | 로컬 필터·평균 |
| 2 | 기간=2026-08, 평균 | segment=A | 40 | 원본에서 기간·그룹 필터·평균 |
| 3 | 기간=2026-08, segment=A | 평균→중앙값 | 20 | 원본 값으로 중앙값 |
| 4 | segment=A, 중앙값 | 이전 달=2026-07 | 4 | 보유 원본에서 기간 전환·중앙값 |

첫 두 턴은 우연히 같은 평균이다. 따라서 수치 통과만으로 그룹 필터 적용을 증명하지 않는다. 보고서 observations의 SQL 및 결과 출처를 함께 확인한다. 답변 문장의 의미 정확성과 불필요한 되묻기 여부는 별도 검토한다.

## 재현 방법

```sh
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python test_scenario.py --static-only
.venv/bin/python scripts/validate_analysis_agent.py --live-local-model
```

마지막 명령은 localhost Ollama와 합성 데이터만 사용한다. 실 Databricks 연결 도구를 실행하지 않는다. 결과는 `analysis_acceptance_results.json`에 저장한다. 실패 기준이 있으면 exit code 1을 반환한다. `--live-local-model`을 생략하면 결정적 계약 검사만 실행하고 해당 파일을 새 결과로 갱신한다.

## 현재 확인한 구조적 실패와 우선순위

1. **단순 승인 상태 질문이 제안을 무효화한다.** `AnalysisSession.submit`이 매 발화마다 `ApprovalQueue.advance`를 실행한다. M1에서 사용자 발화와 승인 응답의 인터페이스를 구분하고, M3–M4에서 상태 질문을 포함한 interrupt 처리 계약을 검증해야 한다. 단순 키워드 예외 추가로 해결하지 않는다.
2. **같은 ID로 만든 세션에 과거 대화가 복원되지 않는다.** 현재 저장소가 객체 내부 메모리뿐이다. M3에서 영속 checkpoint와 별도 자산 저장소를 구현해야 한다. 이 검사는 객체 재생성 검사이며 실제 프로세스 장애 시험은 아직 아니다.
3. **조회 제출 후 응답 유실은 별도 미검증이다.** 현행 메모리 승인 큐의 중복 실행 차단 성공을 서버 재시작 또는 DB exactly-once 보장으로 확대 해석하면 안 된다. M4 실행 기록과 UNKNOWN 상태 처리 후 실제 강제 종료 시험이 필요하다.

기존 코드와 운영 의존성은 이번 기준선 검증에서 변경하지 않는다. 다음 구현은 M1 도구/runtime 경계 분리이며, 동일 검증을 새 런타임에 연결할 수 있게 한다.

## 이번 실행 결과

- 기존 unittest: 26/26 통과. 기존 static suite: exit 0, 시각화 self-eval 10/10.
- 새 결정적 계약: 5/7 통과. 승인 상태 질문과 객체 재생성 복원은 실패.
- 실제 localhost Ollama: 4턴 중 3턴 통과. 3번째 중앙값 요청은 TimeoutError로 실패. 자동으로 시간 제한을 늘리거나 재실행하여 실패를 숨기지 않았다.
- 성공한 1·2·4턴의 실제 SQL에서 각각 기간, 기간+그룹, 이전 달+그룹+중앙값을 확인했고 답변 수치도 일치했다.
- 3번째 요청 실패 후 4번째 요청은 같은 세션에서 성공했으나, 실패한 요청 자체가 완료된 것은 아니다.
- 차트 추천 도구는 실제 PNG 3개를 반환했다. 브라우저에서 두 번째 카드 선택 및 후속 수정은 미검증이다.
- 실 Databricks 호출: 0회. 승인 계약의 execute는 호출 횟수를 기록하는 로컬 대역이다.

후속 구현에는 모델 응답 시간·도구별 지연 계측과 timeout 후 미완료 작업 표시도 포함한다. timeout을 SQL/계산 오류로 단정하지 않는다. 관측된 실패를 해결하고 동일 시나리오를 재평가한 뒤 전환한다.
