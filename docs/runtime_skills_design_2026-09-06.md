# Telly 런타임 스킬 구성

스킬 파일과 registry 계약은 보존한다. 런타임 연결 및 승인 재개 방식은 [LangChain/LangGraph 전환 설계](langchain_migration_design_2026-09-06.md)를 따른다.

상태: 스킬 콘텐츠와 registry/read 도구를 새 AnalysisSession 및 Telly 화면에 연결했다. 실제 모델 품질과 긴 세션 관리 검증은 진행 중이다. 아래 문서의 전체 목표가 모두 구현되었다는 의미는 아니다.

## 개발 스킬과 제품 스킬
AGENTS.md가 참조하는 chatbot_project_manager/project_logger는 개발 보조 agent의 작업 지침이다. Telly 분석 agent가 자동으로 읽는 파일이 아니다. `analysis_skills/*/SKILL.md`는 Telly 사용자 요청 처리에 쓸 제품 런타임 콘텐츠다. 전역 Codex 설치 디렉터리와 분리했다.

## 추가한 스킬
- dataframe-reuse: 데이터 충분성, 범위 축소/확대, 원본/집계 구분.
- chart-recommendations: 통계 기반 실제 이미지 후보와 선택 후 수정.
- period-comparison: 후속 대화의 조건을 유지한 기간 비교.
- analysis-explanation: 근거와 가설을 구분하는 분석 설명/추가 탐색.

고정 컬럼명/테이블명/업무 지표는 스킬에 넣지 않는다. 선택한 dataset의 TableContext 및 외부 도메인 문서에서 읽는다. 스킬 파일은 모델 학습이나 실행 도구를 대체하지 않는다.

## agent와 연결하는 방법

1. 배포 시 신뢰한 analysis_skills 경로에서 SKILL.md frontmatter(name/description)를 검사해 registry를 만든다. 중복 이름/부정확한 경로/잘못된 문서는 제외하고 운영 로그를 남긴다.
2. 주 분석 agent에는 사용 가능한 스킬의 이름과 설명만 전달한다.
3. agent가 사용자 목표와 현재 대화에 맞는 스킬을 골라 `read_analysis_skill(name)` 도구로 본문을 읽는다. 사용자가 명시한 스킬도 같은 경로로 읽는다. 키워드에 따라 실행 흐름을 강제 전환하지 않는다.
4. 스킬 본문을 같은 세션의 tool result로 제공하고 필요한 분석 도구를 실행한다. 한 요청에 여러 스킬을 적용할 수 있지만 무관한 스킬을 모두 주입하지 않는다.
5. 질문/승인 대기는 원래 세션에서 재개한다. 스킬 사용으로 대화 history를 교체하거나 새 SQL/EDA 대화를 시작하지 않는다.
6. 본문 크기 제한과 content hash/version을 기록한다. 변경된 파일은 다음 적용 시 새 버전을 읽고 실행 중 작업은 적용한 버전을 추적한다. 긴 세션의 요약에는 현재 적용한 스킬 ID와 중요한 확정 조건을 남긴다.

## 스킬·도구·정책의 역할

스킬: 어떻게 분석할지에 대한 재사용 지침.
도구: 실제 데이터 검사/조회/계산/차트 생성.
세션: 이전 대화와 도구 관찰 및 데이터/결과 참조.
서버 정책: 승인, 권한, 데이터 범위, 계산 예산과 실행 제약.

특히 Databricks 재조회 승인은 항상 적용되는 서버 정책이다. dataframe-reuse 스킬을 읽었을 때만 적용하거나 스킬 문구로만 보호하지 않는다. 현재 새 Telly 경로는 승인 큐와 실행 어댑터에서 승인 상태를 검사한다. 스킬의 문구 자체가 실행 권한을 주지는 않는다. 재시작·중복 재개·모든 원격 경로에 대한 영속 차단 보장은 후속 전환의 검증 대상이다.

문서/CSV/DB 셀/사용자 첨부를 자동으로 실행 가능한 스킬로 등록하지 않는다. registry는 앱에서 관리하는 콘텐츠만 노출한다. read 도구는 등록된 ID를 실제 경로에 매핑하며 임의 경로/외부 URL을 읽지 않는다. 스킬 내 scripts가 추가되더라도 자동 실행하지 않고 등록된 실행 도구 및 동일 정책을 적용한다.

## 초기 런타임 검증

- 스킬 없이 답할 수 있는 요청에는 불필요하게 로딩하지 않음.
- '월별로 비교 → 그중 특정 그룹 → 이전 기간 → 중앙값' 대화의 조건 유지.
- 재사용 스킬 미선택/읽기 실패에도 DB 승인 gate는 동작.
- 차트 선택이 DB 조회 승인으로 취급되지 않음.
- 스킬에서 참조한 도구가 없을 때 생성/실행 성공을 주장하지 않음.
- 해석 스킬이 상관을 원인으로 단정하지 않음.
- 데이터와 통계 근거가 바뀌면 결과/이미지 버전을 갱신함.

초기 구현 순서는 단일 주 agent loop와 세션 → 필수 DB 승인 gate 및 데이터 도구 → registry/read_analysis_skill → 이미지 추천 UI였으며 현재 부분 연결되었다. 이후에는 전환 설계의 M0–M7 순서로 런타임을 교체하고 실제 모델 다중 턴 평가를 확장한다. 현행 분리 경로에 본문만 붙이는 작업을 완성된 스킬 런타임으로 간주하지 않는다.
