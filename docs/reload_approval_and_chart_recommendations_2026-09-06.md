# Databricks 재조회 승인 및 이미지 기반 시각화 추천 설계

제품 요구는 유지한다. 아래 자체 승인 큐의 상태/실행 흐름과 파일 변경 계획은 초기안이며, 전환 시 [LangChain/LangGraph 전환 설계](langchain_migration_design_2026-09-06.md)의 HITL·실행 기록·UI 경계 및 단계별 계획으로 대체한다. 두 승인 관리기를 동시에 사용하지 않는다.

작성일: 2026-09-06. 상태: 자체 AnalysisSession에서 승인·이미지 추천 MVP가 부분 구현됨. 영속 재개·장애 복구 및 전체 수용 기준은 미완료.
사용자 요구: Databricks 데이터를 다시 읽을 때 반드시 물어본다. 자주 사용하는 시각화는 통계에 기반한 미리보기 이미지로 추천한다.

## 제품 흐름

사용자 발화 → 같은 분석 세션에서 의도 해석 → 데이터 재사용 검사 → 충분하면 현재 데이터 통계/차트 추천 → 이미지 선택 → 최종 차트와 해석.

부족하면 조회 제안과 승인 카드 → 사용자 승인 → 승인된 조회 실행 → 새 데이터 자산 등록 → 원래 요청 재개 → 차트 추천.

UI 표시용 메시지와 별개로 대기 작업을 저장한다. Streamlit rerun은 새로운 실행이나 승인으로 간주하지 않는다.

## 1. Databricks 재조회 정책

- 새 요구 때문에 Databricks를 다시 읽는 작업은 실행 전에 매번 명시적 승인을 받는다. agent 판단, 이전 승인, 차트 선택, 페이지 rerun, 시간 경과는 새 조회 승인이 아니다.
- 로컬 DataFrame 필터/집계/차트 재렌더링은 재조회 승인이 필요 없다.
- 추천 준비를 위한 원격 COUNT/profile/schema refresh 등도 무단으로 실행하지 않는다. 필요한 원격 작업은 제안 카드에 포함한다.
- 차트 선택 후 부족한 데이터를 발견하면 같은 승인 흐름을 거친다.
- 초기 로딩은 사용자가 내용이 표시된 '불러오기'로 직접 요청하는 별도 흐름을 유지한다. 그 이후 추가/갱신/재조회는 본 정책을 적용한다.
- 실행 계층에서 승인 검증을 강제한다. 프롬프트 문구에만 의존하지 않는다. SQL agent, controlled flow, sidebar refresh, table training, 향후 Python/DB 도구 모두 관련 원격 재조회가 승인 gate를 우회하지 않도록 연결한다.

### 승인 카드 예시 — 문구는 예시이며 실제 조회 아님

추가 데이터를 불러올까요?
현재는 8월 A 모델 데이터만 있습니다. 7월과 비교하려면 7월 데이터가 필요합니다.
- 가져올 범위: 7월과 8월, A 모델
- 처리: DB에서 월별 오류 건수 집계
- 기존 데이터: 유지하고 비교 결과를 추가
- 예상 크기: 확실한 근거가 있을 때만 표시. 모르면 '조회 전 정확한 크기는 알 수 없음'
[불러오고 계속] [현재 데이터로 보기] [취소]
상세 보기: 대상 테이블, 컬럼, 기간/시간대, 필터, 집계, 실행 SQL/작업 목록

'현재 데이터로 보기'는 원래 비교를 충족했다고 표시하지 않는다. 가능한 범위의 대안 차트를 보여주고 빠진 기간을 설명한다.

### 승인 범위와 실행 계약

PendingDataRequest:
- request_id, conversation_id, original_goal/원래 요청, continuation
- base_dataset_id/version, intent_revision
- 표시한 데이터 범위 및 정확한 query/parameter 목록
- query fingerprint, reason, created_at, status
- approved_by/approved_at, execution_id, result_dataset_id

SQL 문자열만 아니라 바인딩 값, table/source 및 snapshot 조건까지 승인 fingerprint에 포함한다. 승인 후 값/조건/SQL을 변경하면 재승인한다. 필요한 여러 쿼리는 목록을 보여주고 하나의 명시된 묶음으로 승인받을 수 있다. 일부만 보여주고 추가 쿼리를 실행하지 않는다.

상태: PROPOSED → APPROVED → EXECUTING → COMPLETED 또는 FAILED.
분기: PROPOSED → DECLINED / CANCELLED / INVALIDATED.

버튼 클릭과 관련 발화는 request_id에 묶는다. 단일 카드가 명확히 대기 중일 때 '응, 불러와' 같은 명시적 응답을 그 카드에 연결할 수 있다. 불명확한 긍정 또는 여러 요청이 대기하면 추정 실행하지 않는다. 조회 범위를 바꾸는 사용자 발화가 오면 이전 카드를 무효화하고 새 제안을 만든다.

approval token은 서버에서 생성/검증하고 agent가 스스로 생성할 수 없게 한다. 실행 상태는 원자적으로 전환해 더블 클릭/rerun 중복 조회를 막는다. 이 토큰은 한 승인 작업의 중복 방지용이며 Databricks 자체의 exactly-once 실행을 보장한다는 의미는 아니다.

오류 시 기존 DataFrame을 유지한다. 승인된 작업의 상태 확인은 기존 작업 ID로 하며, 새 제출/수정 조회에는 다시 승인받는다. timeout으로 실행 여부가 불명확하면 자동 재제출하지 않는다. 취소 시 실행 중 작업의 실제 중단 여부를 확인하고 UI에 반영한다. 프로세스 재시작 시 미완료 작업을 자동 실행하지 않는다.

## 2. 통계 기반 시각화 추천

입력: 현재 dataset ID/version, 대화에서 파악한 관심 지표/대상, coverage/grain/aggregation metadata.
통계는 보유 DataFrame 또는 저장된 프로파일에서 계산한다. 통계를 구하려고 승인 없이 DB에 접근하지 않는다.

로컬 프로파일: dtype, 유효값/결측 비율, 고유값 수, 사분위수/IQR, 분포 치우침, 시간 범위/간격, 범주 빈도, 제한된 후보 쌍의 상관과 유효 표본 수. ID성 컬럼/상수 컬럼은 우선 제외하며 숫자형 코드도 자동으로 연속 측정값 취급하지 않는다.

먼저 통계적 적합성을 검사하고, 그 다음 사용자 목적과 관련성으로 정렬한다. 상관계수가 크거나 이상치가 많다는 이유만으로 관련 없는 컬럼을 최고 추천하지 않는다. 이전 요청에서 관심 지표가 확인되면 유지한다. 목적이 없으면 현재 데이터 개요용으로 2~3개 서로 다른 후보를 보여준다.

| 데이터와 목적 | 기본 이미지 후보 | 필수 확인 |
|---|---|---|
| 숫자값 분포 | 히스토그램, 박스플롯 | 원본 관측값, 유효 표본/상수 여부 |
| 범주별 빈도 | 가로 막대 | 범주 수, 상위 N과 제외/기타 처리 표시 |
| 시간에 따른 변화 | 선 그래프 | 시간 정렬, 집계 간격/함수, 빈 구간 표시 |
| 그룹별 측정값 비교 | 박스플롯 또는 요약 막대 | 원본/집계 구분, 그룹별 표본 수, 평균/중앙값 구분 |
| 두 수치의 관계 | 산점도 | 유효 쌍 수, 과밀/표본 표시, 상관은 인과로 설명하지 않음 |
| 여러 수치 관계 | 상관 히트맵 | ID/상수 제외, 결측 처리, 표본 수, 컬럼 개수 제한 |

MVP는 기존 matplotlib renderer를 재사용해 히스토그램/박스플롯/막대/선/산점도/히트맵부터 시작한다. pairplot/violin/복잡한 다중 축은 기본 3개 추천에서 제외하고 확장 후보로 둔다. 현재 grouped bar 경로의 stat_value 처리/재집계가 실제 지표 의미를 유지하는지도 구현 시 별도 검증한다.

### 추천 카드

각 카드: 실제 데이터로 렌더링한 이미지 + 목적 제목 + 컬럼/지표 + 추천 이유 한 줄 + 범위/표본 여부 + 선택 버튼.
예: '온도 분포 보기' / '높은 값 쪽으로 치우친 정도를 확인합니다.'
추천 이유는 실제 계산된 통계가 뒷받침할 때만 표시한다. 데이터 분석 이미지는 이미지 생성 AI로 꾸미지 않는다.

선택은 도구 선택 UI이며 사용자에게 차트 문법이나 축 이름을 긴 문장으로 쓰게 하지 않는다. 카드 선택 후 제목·축·기간·그룹·평균/중앙값 등 간단한 조절을 제공한다. 선택 결과는 conversation에도 명시적 사용자 행동으로 기록해 후속 발화가 참조할 수 있게 한다.

Recommendation:
- recommendation_id, dataset_id/version, intent_revision
- config: columns, chart type, filters, aggregation, time bin, sample policy/seed
- stats evidence, reasons, coverage label, preview artifact, render hash

썸네일과 최종 차트는 같은 config 및 전처리를 사용한다. 확대 시 해상도만 바꾼다. 점수/데이터를 바꾸면 새 카드로 갱신하며 stale 카드 클릭을 막는다. 데이터 갱신과 thumbnail 갱신은 version으로 연결한다.

### 대용량 및 정확성

- 원본 데이터 전체를 LLM에 보내지 않는다. 제한된 통계와 artifact ID를 전달한다.
- 대용량 통계/렌더링은 필요한 컬럼에 한정하고 계산 예산을 둔다. 샘플로 추정한 통계는 표본 기반이라고 표시한다.
- 분포 집계와 시간 binning은 가능한 보유 데이터 전체에서 계산한다. 산점도는 렌더링 표본을 쓸 수 있지만 전체 통계와 구분한다.
- sample/truncated DataFrame의 이미지는 '현재 로딩된 N행 기준'으로 표시한다. 원본 전체 대표성은 추정하지 않는다.
- 집계 결과에서 원본 분포를 만들지 않는다. 그룹별 평균을 다시 단순 평균하지 않는다.
- 계산 불가/부적합 후보는 제외한다. 유효한 후보가 하나뿐이면 하나만 보여준다. 완전한 빈 결과에는 차트 대신 결과 없음과 조건 조정 선택을 제시한다.

## 3. 구성 및 파일 변경 계획

새 계층 예시(이름은 제안):
- core/data_access.py: 모든 재조회 승인 검증 및 실행 진입점
- core/pending_actions.py: 승인 상태/원래 작업 재개/중복 방지
- utils/dataset_profile.py: 로컬 통계 및 캐시
- utils/chart_recommendations.py: 적합성 검사/후보 정렬/config 생성
- ui/reload_approval.py, ui/chart_recommendations.py: 승인 카드/이미지 선택 UI

기존 core/chat_flow.py와 pages/Telly.py는 사용자 발화뿐 아니라 승인/선택 이벤트도 같은 분석 세션으로 전달하도록 바꾼다. utils/data_context.py의 충분성 검사를 재사용/보완하고 utils/session.py 및 모든 DB 접근 경로가 공통 승인 진입점을 사용하도록 한다. 저장소는 대화별로 격리하고 UI rerun 이후에도 pending 상태를 유지한다.

## 4. 수용 기준

승인:
- 재조회 필요 판단만으로 DB 실행 횟수가 증가하지 않는다.
- 거절/취소/무응답 시 DB 실행 0회, 기존 데이터 유지.
- 승인 1회 및 반복 클릭/rerun에서도 동일 작업 중복 제출 없음.
- 승인 후 SQL/조건/대상 변경, 실패 후 새 재시도는 재승인.
- 승인 완료 후 원래 질문의 분석이 이어짐.
- controlled/SQL agent/sidebar/profile 경로가 승인 gate를 우회하지 않음.

추천:
- 추천 생성 자체로 원격 쿼리가 실행되지 않음.
- 원본/집계 데이터에 맞는 차트만 추천.
- 카드와 최종 차트의 데이터/config 일치.
- 사용자 선택과 후속 '그중', '같은 조건' 요청이 같은 dataset/config를 참조.
- 데이터 교체 시 예전 카드 사용 차단.
- 표본/잘림/빈 데이터와 시간 결측 등 제한을 정확하게 표시.

구현 순서: 공통 재조회 승인 gate → 원래 작업 재개 → 실제 데이터 이미지 카드 3개 → 조절 UI와 다중 턴 평가.
