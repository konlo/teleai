# 실제 모델 경로 성능 점검 — 2026-09-14

## 측정 결과

격리된 `bank_loan` 2,000행 fixture에서 `age`와 `balance`의 피어슨 상관계수를 요청했다. 실제 production graph와 로컬 `gemma4:e4b`를 사용했고, 결과가 pandas 독립 정답과 일치할 때만 PASS로 판정했다. Databricks 도구와 실행기는 등록하지 않았다.

- 정확성: 5/5 PASS
- p50: 77.451초
- p95·최대: 80.704초
- 매 turn 모델 호출: 1회
- 전체 시간 중 모델 호출: 74.814~80.479초
- 원격 조회: 0회
- peak RSS: 218,464,256 bytes

`num_predict`를 4096에서 1024로 낮춘 비교 1회도 75.023초였으므로 긴 최종 답변이 병목은 아니었다. 나머지 네 번은 같은 비용의 반복을 피하기 위해 중단했다. HTTP client의 60초 timeout은 streaming 응답의 전체 벽시계 deadline이 아니라 읽기 비활성 timeout으로 동작하므로 60초를 실제 최대 응답 시간이라고 표시해서는 안 된다.

## 적용한 개선

두 개의 수치 컬럼이 명시된 피어슨 상관계수 요청은 이제 보유한 complete raw DataFrame에서 검증된 DuckDB `CORR` 계산으로 전이한다. 컬럼이 정확히 두 개이고 둘 다 수치형이며 출처가 하나로 확정될 때만 적용한다. 수정 후 동일 요청 30회는 pandas 정답과 모두 일치했고 p50 0.037초, p95 0.046초, 최대 0.061초, 모델·원격 호출 0회였다.

이는 자주 쓰는 상관계수 요청의 병목을 없앤 결과다. 모델이 반드시 필요한 모든 질문의 성능이 해결됐다는 뜻은 아니다. 실제 모델 동시 부하와 배포 환경 표본은 여전히 필요하다.
