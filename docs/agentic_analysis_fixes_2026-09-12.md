# 분석 agent 수정 및 검증 — 2026-09-12

## 변경한 동작

- 수치 계산은 해당 요청에서 실제로 실행된 결과 데이터가 있어야 완료된다. 스키마 설명, 이전 요청의 결과, 모델이 작성한 숫자만으로 완료하지 않는다. 지원하는 집계 연산과 컬럼·출처를 확인하고 최종 숫자는 결과 DataFrame에서 출력한다.
- 컬럼 목록·개수 질문은 저장된 테이블 메타데이터를 근거로 답하며 행 데이터 로딩이나 수치 SQL을 요구하지 않는다. 단순히 이전 결과를 설명하는 요청도 새 계산 의무와 구분한다.
- SQL 전에 적용한 `requested_conditions`도 계산 근거에 포함한다. `그중`, `말고` 등의 후속 요청은 이전 집계 의무를 이어받되 완료 근거는 새로 요구한다.
- `prepare_histogram`은 검증된 기존 COUNT 집계와 PNG, 또는 충분한 원본 데이터를 먼저 재사용한다. 로컬 완료가 가능하면 추가 모델 호출이나 원격 조회 없이 결과를 표시한다. 원격 조회가 필요하면 기존 HITL 승인 경로를 거친다.
- `TABLESAMPLE`, `OFFSET`, `LIMIT`, 잘린 결과는 전체 모집단으로 간주하지 않는다. 로컬 계산은 요청 범위가 캐시에 포함되는지 검사하며 안전한 원본 필터·투영의 계보를 보존한다.
- 빈도 히스토그램은 실제 `값, COUNT(*) GROUP BY 값` 실행 계보를 검사한다. 임의의 정수 열이나 SUM 결과를 빈도로 사용하지 않는다. 예전 저장 데이터의 인용된 테이블 이름도 비교할 수 있다.
- 승인 대기 중 요청 변경은 이전 승인을 무효화하고, 기존 도구 응답을 닫은 뒤 실제 새 사용자 메시지로 시작한다. 이 전환 중 중단돼도 checkpoint에서 새 요청을 복구한다.
- 같은 실패 호출 2회, 모델 10회, 도구 12회, 누적 모델/요약 구간 180초로 반복을 제한한다. 사용자 승인 대기 시간은 누적하지 않는다. 개별 호출의 기존 timeout도 유지한다. 전체 작업에 대한 강제 종료 타이머는 아니다.
- DuckDB/SQL 파싱 오류를 구조화된 관찰로 반환하여 수정할 수 있게 한다. 지정된 단일 DataFrame의 알려진 컬럼만 참조하면서 FROM을 생략한 경우에만 `FROM data`를 자동 추가한다. 컬럼·필터·원격 출처를 추측해서 수정하지 않는다.
- 캐시에서 만들어진 `prepare_histogram` 이미지도 Streamlit에서 표시하며 같은 이미지를 반복 출력해도 버튼 키가 충돌하지 않는다.
- 모델/요약 시간, 도구 오류·자동 보정, 완료 판정 이유, 근거 데이터/차트 ID를 `runtime.jsonl`에 남긴다. 예외 원문·데이터 행·자격 증명은 진단 로그에 넣지 않는다.

## 남는 출시 한계

이 수정은 모든 자연어 요청의 의미를 증명하는 범용 검증기가 아니다. 복잡한 비교·조인·복수 지표·암묵적 조건 및 동의어의 해석, 요청과 SQL의 전체 의미 일치에는 추가 정답 평가가 필요하다. 단순 집계 의무 분류는 외부 컬럼명과 제한된 언어 패턴을 사용한다. 모델이 잘못된 SQL 수식을 선택하는 모든 경우를 막았다고 주장하지 않는다.

이번 검증은 새 실제 Databricks 재조회·인증 갱신을 수행하지 않았다. 실제 데이터 검증은 저장된 집계의 재사용이다. 대규모 메모리·보존기간·동시 사용자 부하, 모든 차트 편집, 200문항 전체 모델 성능과 출시 지연시간 기준은 미검증이다. 따라서 전체 기능 출시 준비 완료로 판정하지 않는다.
