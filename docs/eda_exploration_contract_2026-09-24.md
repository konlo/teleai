# EDA 연속 탐색 요구사항·평가 계약

작성: 2026-09-24 · 상태: **구현 전 설계 / 평가 미실행**

상위 기준: [전체 agent 요구사항](data_agent_requirements_and_evaluation_2026-09-24.md). A01~A09, D01~D06, N01~N03, V01~V08과 연결한다. 이 문서는 별도 agent나 프레임워크 도입을 요구하지 않는다. 기존 AnalysisPlan·dataset·artifact·approval 계약을 확장한다.

## 1. 제품 동작

사용자는 “이 데이터 EDA 해줘”라고 요청할 수 있어야 한다. Agent는 사용할 수 있는 데이터와 목적을 확인하고, 기본 탐색을 수행한 뒤 실제 차트와 관찰을 제공한다. 데이터가 선택되어 있고 로컬에서 충분히 탐색 가능하면 사용자가 컬럼·차트 종류·해결 순서를 지정할 때까지 기다리지 않는다. 분석 목적이 없으면 기술적 요약부터 시작하며 목표 변수나 업무상의 성공 기준을 임의 지정하지 않는다.

기본 흐름은 **데이터 확인 → 탐색 계획 → 프로파일·시각화 → 관찰 검증 → 가치 있는 후속 탐색 → 비교·요약**이다. 지원된 로컬 작업은 요청 예산 안에서 자율적으로 이어간다. 원격 조회가 필요한 단계, 분석 의미를 결정할 수 없는 단계에서만 필요한 질문을 한다. 사용자는 언제든 관심 항목을 선택하거나 방향을 바꾸고 중단할 수 있다.

자동 EDA는 무한 탐색이 아니다. 초기 제안 설정은 이미지 최대 6개, 첫 화면에 상위 3개, 검증된 관찰에서 파생한 후속 탐색 최대 2단계다. 더 적은 차트가 적절하면 개수를 채우지 않는다. 값은 향후 실측으로 조정하는 설정이며 완료율·SLO가 아니다. 사용자에게 명시적으로 요청받은 차트는 필수 산출물로 우선 계획하되, 자동 추천과 합산한 전체 시간/비용/메모리 예산을 넘지 않는다. 예산 소진 시 수행한 범위와 미탐색 항목을 보고한다.

## 2. 탐색 범위와 선택 기준

| 관점 | 후보 시각화·분석 | 선택·검증 조건 |
|---|---|---|
| 데이터 품질 | 컬럼별 결측 비율, 중복·상수·범위 요약, 필요한 경우 결측 동시 발생 그림 | 전체 행수/유효 행수와 분모 명시. 결측 비율만으로 결측 발생 원인 단정 금지 |
| 단변량 수치 | histogram, ECDF, boxplot | 타입·유효 건수·분포 확인. 상수/전부 NULL은 설명으로 대체. 음수·극단값을 자동 삭제하지 않음 |
| 단변량 범주 | 빈도/비율 막대, Top-N+기타 | 고유값·불균형·NULL 처리. ID 후보의 거대한 막대그래프 자동 생성 방지, 명시적 요청은 별도 처리 |
| 수치 간 관계 | scatter, density/hexbin, 선택된 컬럼의 상관 heatmap | 유효 pair 수와 결측 제외 기준, 상수·중복 컬럼 처리. 모든 컬럼 쌍을 무조건 계산하지 않음 |
| 집단 간 차이 | 그룹별 boxplot/분포, 그룹 건수·지표 비교, 필요 시 신뢰구간 | 집단별 표본 수, 동일 bin·단위·축 범위, 희소 집단 표시. 평균만으로 차이를 설명하지 않음 |
| 범주 간 관계 | 교차표 heatmap, grouped/stacked bar | 건수/행 비율/열 비율의 분모를 명시. 큰 교차표는 사전 크기 검사 |
| 시간 변화 | 기간별 건수·지표 추이, 기간 비교 | 시간 의미·timezone·bucket 확인. 빈 구간을 관측된 0과 구분, 가중 집계 유지 |
| 관심 구간 확대 | 이상치 구간, 필터 전후, 선형/로그 축 비교, cohort 비교 | 원본과 확대 결과를 함께 추적. 로그 변환의 0/음수 처리와 제외 건수 명시 |

모든 차트를 초기 출시 필수라고 암묵적으로 선언하지 않는다. 위 후보별 capability 지원·미지원과 평가 상태를 T01에서 명시한다. 미지원 renderer는 동등한 정보의 검증된 표현으로 대체할 수 있지만 사용자가 특정 표현을 명시한 경우 임의 대체를 원요청 완료로 처리하지 않는다.

추천은 목적 적합성, 데이터 타입·품질, 분포 특징, 이미 보여준 정보와의 중복, 계산 비용으로 순위를 정한다. 정렬 근거가 되는 통계·scope를 보존하고 “첫 수치형 컬럼”만 반복 선택하지 않는다. 데이터가 뒷받침하지 않는 흥미로운 패턴을 꾸며내지 않는다. 무작위·패턴 없는 fixture에서는 유의미한 발견이 없다는 결과도 정상이다.

## 3. 발견에서 다음 행동으로 이어지는 계약

| 확인한 관찰 | 가능한 후속 행동 | 금지되는 해석·변경 |
|---|---|---|
| 긴 꼬리 또는 극단값 | 전체 분포와 중앙 구간 확대 비교, 유효하면 로그 축, 해당 cohort 점검 | 극단값=오류로 단정하거나 자동 제거 |
| 집단별 지표 차이 | 집단 크기·분포 확인, 근거 있는 추가 변수로 나눠 비교 | 작은 집단의 큰 비율을 확정적 결론으로 제시 |
| 전체 관계와 집단별 관계 불일치 | 전체/집단별 그림과 수치를 같은 범위에서 비교 | 상관을 인과로 설명하거나 목표에 맞는 집단만 선택 |
| 시간 구간 급변 | 전후 기간의 표본 수·구성·결측을 점검 | 데이터만으로 사건의 원인을 만들어냄 |
| 특정 컬럼 결측 집중 | 관측 가능한 다른 그룹/기간과 결측률 비교 | 결측 처리로 모집단을 조용히 변경 |
| 도구·렌더러 오류 | 관찰된 오류를 분류하고 인자 수정·대체 도구로 복구, 결과 재검증 | 차트 실패를 데이터 부족으로 간주해 자동 원격 재조회 |

후속 후보에는 관찰 ID, 확인할 질문, 필요한 데이터, 선택 이유, 예상 비용을 둔다. 단지 p-value가 작다는 이유로 후보를 계속 늘리지 않는다. 탐색 결과는 탐색적 관찰로 표시하고, 확증적 검정이 요청되면 가정·효과 크기·불확실성과 다중 비교 처리 정책을 별도 계획한다. 가설과 데이터로 확인한 사실은 다른 상태로 보존한다.

## 4. 상태·화면·산출물 계약

EDA 상태는 대화 텍스트와 분리해 저장한다. `exploration_id`, 부모 AnalysisPlan/version, dataset/snapshot/schema, 기본 필터·grain·정확성 모드, 실행 예산, 수행·대기·생략 단계, 관심 차트와 비교 기준, 검증된 관찰과 후속 후보를 포함한다. 구체 필드명은 구현 시 기존 schema와 맞춘다. 늦은 결과 반영·취소·중복 실행은 [실행 revision 계약 R01](design_review_2026-09-24.md)의 공통 정책을 따른다.

관찰 기록에는 계산 결과 참조, 모집단·분모·유효 건수, 발견 내용, 검증 상태, 한계, 관련 차트 ID를 둔다. 모델 설명만 있는 발견은 검증 완료가 아니다. 데이터가 바뀌면 이전 관찰을 새 데이터의 사실로 사용하지 않는다.

각 추천 카드는 **실제 이미지 + 답하는 질문 + 추천 이유 + 범위/표본·근사 표시 + 다음 동작**을 제공한다. “확대”, “그룹별 비교”, “bin 변경”, “다른 차트”, “이전 결과와 비교”가 같은 차트/계획 참조에 적용되어야 한다. 이미지 준비 실패는 실패 상태와 복구 진행을 표시하고 준비되지 않은 이미지를 완료로 안내하지 않는다.

“그중”, “이상치 빼고”, “원래대로”, “다른 그룹과 비교”는 원본을 덮어쓰지 않고 분기된 계획으로 실행한다. 비교 화면의 범위 차이와 제외 건수를 표시한다. 두 차트가 다른 snapshot이면 같은 모집단 비교인 것처럼 정렬하지 않는다. 작업 중 UI에는 현재 단계·완료 산출물·승인 대기·남은 탐색을 보여준다.

완료 시 열린 차트/표, 검증된 주요 관찰, 수행 범위, 생략·미완료 항목, 선택 가능한 다음 질문을 묶는다. 시작 시 데이터에 적합한 필수 관점·선택 후보·적용 불가 사유를 계획에 고정한다. 필수 관점의 실패를 선택 항목으로 바꿔 완료 처리하지 않는다. 유한한 초기 EDA 계획 완료와 “모든 관계를 분석했다”를 구분한다. 요청한 산출물이 실패했다면 부분 완료이며, 유효한 관찰이 없다는 사실 자체는 실패가 아니다.

## 5. 대규모 데이터에서 여러 차트 만들기

[데이터 로딩·원본 보존 계약](data_loading_and_preservation_contract_2026-09-24.md)의 보호 root/파생/집계/후보 역할과 LoadPlan을 적용한다. EDA에서 선택한 파생본이 부족해도 부모·원본을 먼저 찾고, 집계 결과가 탐색 원본을 대체하지 않게 한다. 로컬 원본의 RAM 해제는 허용하지만 영속 보호 snapshot은 분석·재로딩·공간 확보 때문에 삭제하지 않는다. SQL 전체 통계와 로컬 EDA를 함께 사용해도 각 범위·시점·정확성 모드를 구분한다.

- schema와 저장된 프로파일을 먼저 확인해 읽기 계획을 세운다. 실제로 스캔하지 않은 전체 데이터 통계는 unknown/estimate로 남긴다.
- [일관성·재집계 계약 R02/R03](design_review_2026-09-24.md)을 충족하는 경우에만 여러 차트의 projection·필터·그룹·bin·시간 bucket을 묶어 중간 집계를 공유한다. 공통 집계가 지나치게 커지면 분리 실행한다.
- 추천 썸네일도 분석 비용이 든다. 모든 컬럼/컬럼 쌍을 그린 뒤 고르는 방식 대신, 제한 프로파일로 후보를 좁힌 다음 렌더링한다. 후보 컬럼·쌍·그룹 수 한도를 실행 전에 적용한다.
- 로컬 DataFrame/파일로 충분하면 추천·후속 탐색에 새로운 Databricks 실행은 0회다. 원격 통계·집계가 필요하면 정확한 SQL 및 목적을 기존 승인 절차로 제시한다. 탐색 요청을 포괄적 재조회 승인으로 해석하지 않는다.
- raw dataset, 공유 aggregate, plot input, 렌더링 이미지 캐시를 분리한다. 스타일만 변경하면 plot input 재사용, bin/필터 변경이면 충분한 상위 데이터부터 재계산한다. 기존 bin count만으로 더 세밀한 bin을 복원하지 않는다.
- sample은 seed·추출 방식·표본 수·원본 범위를 기록한다. 전체 통계와 표본 그림을 함께 쓸 때 각각 표시한다. 표본에서 희소 집단이 빠질 수 있음을 검증하고 전체 비율/극단값을 표본으로 단정하지 않는다.
- 비교용 chart에는 같은 범위·bin·단위의 공유 spec을 우선한다. 로그 축 등 표현 변경은 단위·범례에 표시하며 계산 지표의 의미를 바꾸지 않는다.

## 6. 구현 전에 고정할 EDA 평가 여정

| ID | 입력·변형 | 독립 합격 조건 | 연결 |
|---|---|---|---|
| J13 | “이 데이터 EDA 해줘” → 최초 이미지 묶음 → 관찰에 따른 후속 탐색 | schema 기반으로 적절한 관점 선택; 실제 이미지와 계산 근거; 후속 행동이 관찰과 연결; 설정 예산 준수 | V03,V05,V06,A08 |
| J14 | 추천 선택 → 구간 확대 → 그룹 비교 → 원래대로 → 재시작 | dataset/snapshot·필터·분모·기준 차트 보존; 원본 불변; 복원 결과 oracle 일치 | V07,A03,A04 |
| J15 | 메모리보다 큰 데이터 → 여러 추천 이미지 → bin/스타일 변경 | 중복 scan/전송·peak RSS·캐시 적중 측정; 스타일 변경 시 집계 재실행 0; 로컬 충분 시 원격 0; 불충분 시 승인 대기 | V08,D01~D06 |
| J16 | 패턴 없음/희소 집단/NULL/음수/상수/그룹 혼합 + renderer 실패 | 허위 발견·인과 단정·자동 삭제 0; 그룹/전체 의미 보존; 복구 가능 오류 후 이미지와 데이터 재검증 | V06,A06,A07,V01 |

fixture에는 수치·범주·시간·결측·긴 꼬리·알려진 그룹 차이를 넣고, schema/컬럼 순서/행 순서/표현을 바꾼 held-out 변형을 둔다. 정답이 있는 관찰뿐 아니라 패턴 없는 대조군도 포함한다. 정답과 예상 후속 행동은 agent에게 노출하지 않는다. J16의 실패 주입은 통계 조건과 독립적으로도 실행해 원인을 구분한다.

채점은 다음 세 층으로 나눈다.

1. **결정적 계약**: 독립 수치 oracle, bin·합계·분모, scope·lineage, 실제 이미지, 승인·예산·캐시 계측. 이미지를 생성했다는 사실만으로 통과하지 않음.
2. **EDA 품질**: 사전 rubric의 적절한 차트/후속 행동 후보 집합, 관점 다양성·중복·관찰 근거·질문 적합성. 유효한 다른 탐색 순서를 허용하고 DeepEval judge를 보조로 사용. 평가자 일치도는 사람이 보정.
3. **실제 화면 여정**: 이미지 가독성·범례·라벨·선택/비교/되돌리기·재시작·부분 완료 표시. 파일 기반 검사와 사용자 화면 증거를 구분.

추천 적합률(top-3에 적절한 후보 포함), 검증된 관찰 비율, 근거 없는 주장 수, 자율 후속 완료율, 불필요한 재조회, 차트당/전체 지연·peak RSS를 별도 보고한다. 차트 수가 많거나 judge 점수가 높다는 이유로 정확성 실패를 상쇄하지 않는다. Spider는 필요한 SQL 탐색/집계 능력 평가에 연결하고 EDA 전체 품질을 대표하는 점수로 사용하지 않는다.

재리뷰 후 경계 시험: J17(실행 중 조건 변경과 늦은 차트), J18(원본 변경 중 여러 집계), J19(부분 집계·타입/단위), J20(context·전역 자원·저장 crash·참조 만료)을 EDA에도 교차 적용한다. 상세는 [설계 재리뷰](design_review_2026-09-24.md)를 따른다. 이미지 생성 성공과 현재 사용자가 보는 이미지의 revision 일치도 함께 확인한다.

원본 소실 회귀: [J21~J24](data_loading_and_preservation_contract_2026-09-24.md)의 반복 EDA 후 원본 복귀·오해석 재로딩·실패한 후보 적재·DB 집계/raw 혼합을 추가한다. 차트 정답과 별도로 원본 ID/digest/행수/읽기 가능 및 불필요한 원격 조회 수를 검증한다.
