# 관찰 기반 분석 복구

요청의 미완료 산출물과 마지막 도구의 구조화 오류를 먼저 확인한다. 같은 호출을 그대로 반복하지 않는다. 기존 성공 결과와 원본은 유지한다.

1. 도구 선택·인자 문제가 있으면 `search_analysis_tools`에 짧은 기능 키워드 또는 정확한 도구명을 넣어 실제 schema와 제약을 읽는다. 반환된 입력 타입·enum·필수 인자로 수정한다.
2. dataset ID가 없으면 `list_analysis_context`에서 실제 ID를 찾는다. 테이블명은 ID가 아니다. `inspect_dataset`으로 실제 schema·범위를 확인하고 원래 기간·조건·집계 수준을 유지한다.
3. 로컬 도구 unavailable이나 SQL 구문 오류이면 같은 raw dataset의 `local_analysis_sql` 또는 동등한 등록 도구를 선택한다. 실패는 0건이 아니며 로컬 오류는 원격 재조회 사유가 아니다.
4. 업무 의미가 없으면 `inspect_column_definitions`로 승인 후 저장된 메타데이터를 찾는다. 없으면 정확한 metadata SQL 승인까지만 요청한다. 모델의 익숙한 테이블 지식으로 값을 추정하지 않는다.
5. 필터 컬럼은 동시에 계산 대상이 될 수 있다. “그중 수치 평균”에서는 기존 조건을 유지하고 명시한 수치를 계산한다. 원본을 집계 결과로 교체하지 않는다.
6. 수치·표·이미지를 실제로 생성하고 요청 범위와 검증한 뒤 완료한다. 일부 산출물만 만든 상태는 전체 완료가 아니다.

추가 원격 조회는 기존 gateway에서 매번 정확한 SQL 승인이 필요하다. 거절·실행 여부 불명·원격 오류는 자동 재시도하지 않는다. 이 스킬은 권한·예산을 늘리지 않으며 임의 코드·파일·네트워크 실행을 허용하지 않는다.
